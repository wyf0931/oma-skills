# Step 1：事实清洗层矩阵（Fact Layer Matrix）

本层把原始、无序的信息，清洗成**客观、全面、无偏见**的数据结构。目标是让任何人在这一步之后，对“到底发生了什么”没有分歧空间——分歧只应留在对事实的解读上，而不是事实本身。

当信息已经结构化（日志、报表、接口文档）时，可以跳过本层，直接进入 Step 2。

## 工具箱选择决策表

| 场景类型 | 推荐框架 | 核心字段结构 |
| :--- | :--- | :--- |
| **单点事件 / 故障还原** | **5W1H** | Who, What, When, Where, Why, How |
| **方案策划 / 项目立项** | **5W2H** | 5W1H + **How Much**（成本）+ **How Many**（收益/数量） |
| **数据波动 / 业务汇报** | **Metric-Variance** | Baseline（基线）, Variance（偏差）, Trend（趋势）, Driver（归因） |
| **系统 / 架构 / 流程分析** | **IPO** | Input（输入边界）, Process（处理逻辑）, Output（产出指标） |
| **宏观环境 / 战略分析** | **SWOT / PEST** | 内部优劣势；外部政治、经济、社会、技术环境 |

## 框架结构模板

### 1. 5W1H（事件还原模板）

- **Who（主体）：** 谁受影响、谁负责、谁在做决定。
- **What（事件）：** 发生了什么，一句话可复述。
- **When（时间）：** 起止时间与持续时间。
- **Where（范围）：** 系统、区域、业务线或用户群。
- **Why（原因）：** 直接原因；根因未定位就写“根因待定位”，不要用猜测顶替。
- **How（路径）：** 事件如何暴露、如何被处理。

### 2. 5W2H（立项模板）

在 5W1H 基础上补两问，这两问通常是决策者最先看的：

- **How Much（成本）：** 人力人天、算力/硬件、采购费用、机会成本。
- **How Many（收益/数量）：** 覆盖用户数、订单量、效率提升倍数、可量化收益。

### 3. Metric-Variance（数据异动模板）

- **Baseline（基线）：** 平时/同期的正常数值是多少？
- **Variance（偏差）：** 当前实际值与基线的绝对值差与百分比差。
- **Trend（趋势）：** 属于周期性正常起伏，还是异常突变（给出时间序列特征）。
- **Driver（归因拆解）：** 按维度（渠道、地区、用户群、版本）下钻后，定位的核心驱动因子及其贡献占比。

### 4. IPO（系统流程模板）

- **Input（输入）：** 上游依赖、数据吞吐量、并发要求、输入数据质量约束。
- **Process（处理）：** 核心算法/流程、资源消耗（CPU / 内存 / RT）、状态变更与异常分支。
- **Output（输出）：** 交付结果、QPS / P99 表现、成功率与异常阻断率。

### 5. SWOT / PEST（环境分析模板）

- **SWOT：** Strengths / Weaknesses（内部）、Opportunities / Threats（外部），每条都要有事实依据，不能只列形容词。
- **PEST：** Political / Economic / Social / Technological，用于说明外部环境变化如何影响本方案。

## 常见失真

- **把判断当事实：** “后端很慢”是判断，“P99 从 200ms 涨到 1.8s”是事实。前者放进 Step 2，后者留在本层。
- **只留结果不留基线：** 没有基线的数字无法判断好坏，Metric 类汇报必须带 Baseline。
- **单维度归因：** 数据波动往往由多个因子叠加。给出 Driver 时同步给出各维度贡献度，避免误导决策。
