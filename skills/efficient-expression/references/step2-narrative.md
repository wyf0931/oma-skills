# Step 2：叙事逻辑层矩阵（Narrative Layer Matrix）

本层把清洗后的事实，按**听众的心理认知路径**组装成有说服力或吸引力的骨架。事实决定“说什么”，本层决定“按什么顺序说才让听众愿意接受”。

选择框架的依据不是作者习惯，而是**你希望听众在听完之后产生什么心理反应**。

## 框架选择矩阵

```text
                  【期望听众产生的心理反应】
                             │
     ┌───────────────────────┼───────────────────────┐
     ▼                       ▼                       ▼
【解决问题 / 做决策】    【建立信任 / 做评估】    【被信念感召 / 去行动】
     │                       │                       │
 ┌───┴───┐               ┌───┴───┐               ┌───┴───┐
 ▼       ▼               ▼       ▼               ▼       ▼
SCQA   PROACT          STAR    ADEPT       Golden Circle  PAS
(危机)  (对比)         (经验)  (教学)        (初衷)        (痛点)
```

## 核心框架详细定义

### 1. PROACT（高管决策框架）

适用于技术选型、重大战略汇报、划拨预算等需要高管拍板的场景。它的价值在于**把“请批准”变成“几选一”**：决策者不需要自己从零思考，只需要在你给出的选项中权衡。

- **P (Problem)：** 核心痛点与决策背景。
- **O (Objectives)：** 决策要达成的量化目标与约束条件（预算、人力、时间、合规红线）。
- **A (Alternatives)：** 穷尽可选方案（方案 A / B / C），包含“不做事”这个基线选项。
- **C & T (Consequences & Trade-offs)：** 各方案的后果对比与权衡（成本 vs 收益 vs 风险）。
- **Recommendation：** 明确给出己方倾向性建议及理由。

对比条目不写成段落，写成一张表——决策者的阅读方式是横向扫维度、纵向比方案。

### 2. SCQA（冲突引发框架）

适用于演讲开场、项目发起、危机公关、跨部门协作提案。它先用共同背景建立安全感，再用冲突制造张力，让“我们要解决它”成为听众自己的结论。

- **S (Situation)：** 听众熟悉的稳定背景。
- **C (Complication)：** 打破平衡的冲突或挑战。
- **Q (Question)：** 基于冲突提出的核心疑问（应由读者自己也在问的那个问题）。
- **A (Answer)：** 我们的解决方案。

**压缩形态：** 在故障通告与事故复盘中，Q 常被内化——受众自己就在问“为什么会发生”，不必再写一遍。段落顺序变为 S → C → A（背景、故障、止损与改进）。即便如此，“为什么会发生”仍必须在正文里被明确回答：**不写根因，读者会自己猜，而猜测通常比事实更糟。**

在协同类场景里，SCQA 的 Q 要写成“我们共同面对的问题”，而不是“你们造成的问题”。

### 3. STAR（经验复盘框架）

适用于案例复盘、绩效谈话、面试行为题。它证明能力的方式是给出**完整的行为闭环**，而不是自我评价。

- **S (Situation)：** 当时的背景与约束。
- **T (Task)：** 你被要求达成什么、衡量标准是什么。
- **A (Action)：** 你具体做了什么（讲动作，不讲决心）。
- **R (Result)：** 结果数据，以及可迁移的经验/教训。

缺 R 的复盘只是讲故事；缺 T 的复盘无法体现难度。四个都要有。

### 4. ADEPT（教学 / 培训框架）

适用于技术分享、科普、产品功能培训。它的顺序遵循认知规律：先建立直觉，再给细节。

- **A (Analogy)：** 生活化类比（建立第一印象）。
- **D (Diagram)：** 可视化架构图或视觉模型。
- **E (Example)：** 实际代码或操作案例。
- **P (Plain English)：** 剔除术语的大白话总结。
- **T (Technical Details)：** 深入底层技术细节。

按这个顺序讲，听众在接收细节时已经有了挂靠点；顺序颠倒会导致“每个字都认识，连起来不懂”。

### 5. Golden Circle（信念感召框架）

适用于产品发布、品牌宣讲、团队动员。它反直觉的地方在于：先讲 Why 而不是 What，因为人对信念的反应先于对功能的反应。

- **Why：** 我们为什么要做这件事（信念与初衷）。
- **How：** 我们用什么独特方式做到。
- **What：** 我们具体交付了什么。

### 6. PAS（痛点框架）

适用于短文案、转化型内容。结构极简：

- **P (Problem)：** 直击对方正在经历的痛点。
- **A (Agitate)：** 放大痛点不解决的代价。
- **S (Solution)：** 给出解决方案与行动号召。

## 常见失真

- **框架混搭：** 一份输出里既 PROACT 又 SCQA，读者会找不到主线。一个受众、一个目标、一个主框架。
- **有 A 无 Q：** SCQA 里跳过 Question 直接给方案，冲突的张力没有转化成“需要答案”的动机。
- **对比不公平：** PROACT 里给自己方案列满优点、给备选只列缺点。决策者一旦察觉，整份汇报的可信度归零。
- **事故复盘下指向人：** 根因写到“机制缺口”（缺少限流、缺少联动）就停住。写成“某团队没做”，复盘就变成甩锅，下一次事故没人敢第一时间上报。
