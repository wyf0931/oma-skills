# Step 3：语言渲染层矩阵（Style & Interface Matrix）

本层把逻辑骨架，按**受众的认知背景与注意力成本**做语言适配。可以把它理解为一次“接口编译”：同一份逻辑，输出给不同受众时要换一套接口协议。

**本层为强制层。** 无论 Step 1 / Step 2 是否被裁剪，输出都必须经过这里。受众读不懂，前面两层的努力等于零。

## 适配决策维度

先给受众定位，再选渲染模式：

1. **Context Gap（专业跨度）：** 同行/技术人员（小）↔ 跨部门同事、C 端用户（大）。跨度越大，术语越要替换或解释。
2. **Attention Budget（精力成本）：** 极度繁忙的高管（低）↔ 学习型学员（高）。预算越低，结论越要前置、长度越要压缩。

| 受众 | Context Gap | Attention Budget | 默认渲染 |
| :--- | :--- | :--- | :--- |
| CEO / 高管 | 大 | 极低 | BLUF + KISS |
| 同级工程师 / 专家 | 小 | 中 | KISS |
| 跨部门 / 产品 / 运营 | 大 | 中 | ELI5 |
| 冲突中的同事 / 下属 | 大 | 中 | NVC |
| 投资人 / 数据评审 | 大 | 低 | Data-In-Context + BLUF |

**渲染模式可以按段落切换，但不能在一段内混。** 长输出（技术分享、培训、产品白皮书）允许前段 ELI5、后段 KISS，这是对同一批受众的渐进式交付；但同一段落里既出现生活化类比又出现未解释的精确术语（`Context Window`），读者会不知道该用什么颗粒度理解。

## 五大渲染模式规范

### 1. BLUF（Bottom Line Up Front — 结论先行）

- **适用：** 汇报给 CEO / 高管、紧急 Slack 消息。
- **规则：** 第 1 句直接给结论与诉求，随后提供 3 个支撑点，最后附上备用细节（被追问时再展开）。
- **理由：** 高管的精力预算只够读第一段，如果第一段没有结论，后面的内容不会被读到。

### 2. KISS（Keep It Simple, Stupid — 精炼直白）

- **适用：** 同级技术沟通、Code Review、专家对齐。
- **规则：** 砍掉所有修饰性形容词，保留精准技术术语（这一层不需要降维），一句话只表达一个逻辑。
- **注意：** KISS 不是把所有术语都删掉。对专家省略术语反而增加沟通成本，KISS 删的是废话，不是精度。

### 3. ELI5（Explain Like I'm 5 — 降维类比）

- **适用：** 面向非技术产品经理、C 端用户、跨部门协同。
- **规则：** **不出现未解释的专业术语**；必须找一个日常生活的实体做类比（Analogy），并保证类比的边界也讲清楚（哪部分像、哪部分不像）。
- **理由：** 类比给新概念提供挂靠点。类比漏掉边界时，受众会顺手推出错误结论。

### 4. NVC（Nonviolent Communication — 非暴力 / 同理心渲染）

- **适用：** 部门权责冲突、延期事故说明、绩效反馈。
- **规则：** 区分“事实”与“评论”（说“鉴权接口格式变更导致联调中断 3 小时”，不说“你们太不负责任”）；先表达对对方处境的理解（Empathy），再提出共同目标，最后给具体补救动作。
- **事故复盘里要求无责（blameless）：** 根因归因到机制缺口，不归因到个人或团队。归因到人，下一次事故就没人敢第一时间上报，组织实际承受的损失更大。
- **理由：** 对方在防御状态下不会处理信息。先降低防御，方案才进得去。

### 5. Data-In-Context（数据语境化）

- **适用：** 数据分析汇报、投资人展示。
- **规则：** 不单抛孤立数字（“增长 15%”没有意义），必须给锚点：环比/同比、行业均值、目标线、历史区间。形式为“增长 15%，是行业平均增速的 3 倍，超出 Q3 目标 5 个百分点”。
- **理由：** 数字本身不构成结论，语境才构成结论。

## 常见失真

- **术语倾泻：** 对业务方讲 P99、幂等、灰度，却不解释。受众不会追问，只会点头然后不执行。
- **过度降维：** 对专家用 ELI5，会被读作“你不专业”。降维程度要严格对齐 Context Gap。
- **数据裸奔：** 只有数字没有锚点，读者只能自行猜测好坏，等于把结论权交出去。
- **结论藏在第三段：** BLUF 场景下把结论写在最后，是最常见的浪费受众精力的方式。
